# Knowledge Wiki — 반입 정책 (Ingest Policy) v1

이 문서는 **사용자와의 계약**이다. 아래 정책을 코드가 집행하며,
사용자가 항목마다 검토할 필요가 없도록 설계됐다.

> **한 줄**: 세션에서 *배운 것*만 일반화해서 쌓는다. 세션에서 *있었던 일*은 쌓지 않는다.

---

## 0. 기본 입장

| 원칙 | 내용 |
|---|---|
| **로컬 우선** | 기본값은 로컬 축적만. **`remote` 없으면 push 하지 않는다** |
| **경계는 유지** | `exclude`·자기오염·deny 경로는 설정과 무관하게 차단 |
| **Fail-closed** | 판정 불가·오류·타임아웃 = 폐기. "일단 쌓고 나중에 지운다"는 없다 |
| **폐기 > 마스킹** | 금지 항목이 하나라도 있으면 **세션 전체를 버린다.** 부분 정제하지 않는다 |
| **원문 미반출** | 위키 항목은 원문 발췌가 아니라 **새로 쓴 일반화 서술**이다 |
| **LLM은 승인자가 아니다** | LLM은 "빼라"만 할 수 있고 "괜찮다"고 판정할 권한이 없다 |

**비용 비대칭**: 위키 항목 하나를 잃는 건 싸다. 유출은 되돌릴 수 없다.
그래서 모든 애매한 경우는 폐기 쪽으로 기운다.

---

## 1. 반입 대상 (allow-list)

이 목록에 해당하는 **일반화된 지식**만 반입한다.

| 유형 | 예 |
|---|---|
| 기술 패턴 | "재시도 로직은 그래프 노드 경계에 둔다" |
| 설계 판단 | 선택지·기각 이유·트레이드오프 |
| 트러블슈팅 | 증상 → 원인 → 해결 (일반화된 형태) |
| 도구 사용법 | 라이브러리 함정, 우회법, 설정 요령 |
| 벤치마크 | 측정 방법과 결과 해석 |

**판단 기준 한 문장**:
> *"이 내용을 외부 컨퍼런스에서 발표해도 되는가?"*
> 안 되면 반입하지 않는다.

## 2. 반입 금지 (deny-list) — 하나라도 있으면 **세션 폐기**

| # | 금지 항목 | 이유 |
|---|---|---|
| D1 | API 키·토큰·비밀번호·인증서·자격증명 | 즉시 유출 |
| D2 | 개인정보 (이메일·전화·주민번호·계좌·실명+소속) | 법적 리스크 |
| D3 | 고객사·조직 식별 정보 (사명, 프로젝트 코드명, 계약 내용) | 계약 위반 |
| D4 | 내부 인프라 (사설 IP, 내부 호스트명, 사내 URL, DB 접속 문자열) | 정찰 정보 |
| D5 | 소스 코드 원문 (프로젝트에서 복사한 코드 블록) | IP 경계 |
| D6 | 절대 경로 · 사용자명이 포함된 경로 | 환경 노출 |
| D7 | 미공개 사업 정보 (가격, 일정, 인사, 미발표 제품) | 기밀 |
| D8 | 제3자에게 받은 비공개 자료의 내용 | NDA |

> D5 주의: **의사코드로 다시 쓴 것은 허용**한다. 복사가 금지지 개념이 금지가 아니다.

## 3. 4단 게이트 — 코드가 집행하는 순서

```
[G0] 스코프 게이트   전역 설정 include 밖 → 종료 (아무것도 안 함)
      │              exclude·deny 경로 → 마커가 있어도 거부
      ▼
[G1] 결정론 차단     정규식으로 D1·D2·D4·D6 탐지
      │              1건이라도 hit → 세션 전체 폐기 (마스킹 X)
      ▼
[G2] LLM 컴파일      transcript → 일반화된 article 초안
      │              원문 인용 금지 · 출력 스키마 강제
      │              "배운 것"만 쓰고 "있었던 일"은 안 씀
      ▼
[G3] LLM 감사        별도 호출. G2 산출물만 검사
      │              D1~D8 잔존 여부 판정
      │              ⚠️ 통과 판정 권한 없음 — 발견 시 폐기 지시만
      │              호출 실패·파싱 실패 → 폐기 (fail-closed)
      ▼
[G4] 결정론 재검사   G3 통과분에 G1 정규식 재적용
      │              LLM이 되살렸을 가능성 차단
      ▼
   per-user/ 에 커밋 + push
```

### 왜 G4가 필요한가

G2·G3은 LLM이다. **LLM 출력을 검증 없이 신뢰하지 않는다.**
G3이 "깨끗하다"고 해도 G4의 정규식이 다시 본다. 결정론이 최종 심판이다.

### 왜 G3이 승인 권한이 없는가

LLM에게 "이거 괜찮아?"를 물으면 대부분 "괜찮다"고 한다.
그래서 G3의 출력은 **`{"violations": [...]}` 형태만** 받는다.
빈 배열이면 통과가 아니라 **"G3이 추가로 찾은 게 없음"**일 뿐이고,
최종 통과 판정은 G1·G4의 결정론이 내린다.

## 4. 게시 경계

| 대상 | 자동화 | 근거 |
|---|---|---|
| `per-user/<name>/` | **자동 커밋 + push** | 개인 스크래치. 리뷰 불필요 |
| `shared/` | **금지** — 사람이 PR로 승격 | 팀 정본은 리뷰를 거친다 |

자동 push는 개인 영역까지다. 팀 공유 지식으로의 승격은 **사람의 명시적 행위**다.

---

## 5. 스코프 판정 순서 (G0 상세)

**전역 설정이 정본, repo 마커는 override다.**

```
0. 위키가 작업 repo 안             → 거부 (자기 오염 방지)
1. deny 경로(node_modules 등)      → 거부 (설정 무관 하드 게이트)
2. 전역 exclude 매칭               → 거부 (⚠️ 마커보다 강하다)
3. repo 마커 있음
     enabled: false               → 거부 (이 repo만 끄기)
     자체 wiki: 블록 있음           → 그 위키로 (다른 목적지)
     없음                          → 전역 위키 + include 검사 면제 (명시적 opt-in)
4. repo 마커 없음
     전역 include 안               → 통과
     그 외                         → 거부
```

**자기 오염을 막는 이유**: 위키를 작업 repo 안에 두면 세션마다 그 repo가 커밋으로
오염되고, 그 커밋이 다음 세션의 입력이 된다. 이전 세대 도구가 작업 repo에 지식 디렉터리를
만들던 안티패턴이 정확히 이것이다. **지식은 항상 별도 repo로 나간다.**

**exclude가 마커를 이기는 이유**: 민감 디렉터리(고객 NDA repo 등)는
누군가 마커를 실수로 커밋해도 열리면 안 된다. 차단은 항상 허용보다 강해야 한다.

---

## 6. 사용자가 해야 할 일

**두 가지뿐이다.**

1. **아무것도 안 한다.** 설치하면 `~/.wigtn/wiki` 에 로컬로 쌓이기 시작한다.
2. 팀 공유를 원할 때만 `remote` 한 줄을 추가하고,
   `per-user/`에 쌓인 것 중 공유할 것을 **PR로 `shared/`에 승격**한다.

항목별 검토는 하지 않아도 된다. 그게 이 정책의 목적이다.

---

## 7. 이 정책이 이렇게 생긴 이유

이전에 비슷한 기능을 쓰다가 **통째로 껐던 경험**에서 나왔다. 당시 문제:

| 당시 | 이 정책 |
|---|---|
| 전역 적용 — cwd 무관하게 흡수 | **G0 스코프 게이트 (include 지정 필수, fail-closed)** |
| "사용자에게 묻지 않는다" | 캡처는 자동, **`shared/` 게시는 사람** |
| 필터 없이 transcript 컴파일 | **G1~G4 4단 게이트** |
| 파이프라인이 죽어도 모름 | **상태 파일 + 마지막 실행 기록** |

껐던 이유는 기능이 나빠서가 아니라 **경계가 없어서**였다.
경계를 코드로 만들면 기능은 그대로 쓸 수 있다.
