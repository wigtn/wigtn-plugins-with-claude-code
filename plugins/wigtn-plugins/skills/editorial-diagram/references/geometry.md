# Geometry — 좌표는 창작하지 말고 읽어 쓴다

여기 있는 숫자는 전부 **4의 배수**로 미리 검산된 값이다. 표에서 그대로 옮겨 적으면
`check.py`의 4px 검사를 자동으로 통과한다. 눈대중 보정이 4px 위반의 주범이다.

---

## 1. 캔버스

**기본 캔버스는 `1280 × 720` 하나다.** SVG는 해상도 독립이므로 문서 인라인용이라고
캔버스를 줄이지 않는다 — CSS 폭만 줄이면 된다. 캔버스를 바꾸는 건 **가로세로비가
진짜 다를 때뿐**이다.

| 프리셋 | viewBox | 마진 | 언제 |
|---|---|---|---|
| **slide-16x9** (기본) | `0 0 1280 720` | 64 | 슬라이드, 문서, README 전부 |
| slide-4x3 | `0 0 1024 768` | 64 | 4:3 프로젝터 강제일 때만 |
| social-og | `0 0 1200 630` | 56 | OG 이미지 |

아래 좌표표는 전부 **slide-16x9 기준**이다. 다른 프리셋은 §7의 파생 규칙을 쓴다.

### 1.1 slide-16x9 밴드

```
x: 64 ─────────────────────── 1216      (content width W = 1152)
y:  64  제목 밴드 시작        (title baseline 96, font 28)
   124  부제/캡션 baseline    (font 15, muted)
   160  ── 본문 영역 시작 ──  (body H = 496)
   656  ── 본문 영역 끝 ──
   692  출처/각주 baseline    (font 12, muted)
```

본문 영역 밖으로 도형을 내보내지 않는다. 제목이 없는 다이어그램이면 본문 영역을
`y: 96 → 656`으로 넓혀도 된다(위쪽 64만 회수).

## 2. Row — 가로 배치 (파이프라인 · 아키텍처 · 카드)

**X 좌표표** (마진 64 기준, 마지막 박스 우변은 항상 1216)

| N | 박스 폭 w | 간격 | x 위치 |
|---|---|---|---|
| 2 | 544 | 64 | `64, 672` |
| 3 | 352 | 48 | `64, 464, 864` |
| 4 | 240 | 64 | `64, 368, 672, 976` |
| 5 | 208 | 28 | `64, 300, 536, 772, 1008` |
| 6 | 152 | 48 | `64, 264, 464, 664, 864, 1064` |

> **모든 폭이 8의 배수다.** 그래야 박스 중심(`x + w/2`)도 4의 배수가 되어,
> 중심에서 출발하는 선(Sequence 라이프라인, Tree 연결선)이 4px 검사를 통과한다.
>
> **화살표가 들어가는 파이프라인은 N ≤ 4.** N=5는 간격이 28이라 화살표가 눌린다.
> 5개 이상이면 화살표 없는 카드 나열로 쓰거나, 단계를 묶어 4개로 줄인다.

**Y 좌표표** — 박스 높이는 **행 수에 따라 바뀐다.** 행이 적을수록 키운다. 1행짜리를
h=96으로 그리면 16:9 캔버스에 여백만 남아 "덜 만든 그림"으로 읽힌다.

| 행 수 | 박스 h | 세로 간격 | y 위치 |
|---|---|---|---|
| 1 | **160** | — | `328` |
| 2 | **120** | 64 | `256, 440` |
| 3 | **96** | 64 | `200, 360, 520` |

행이 2줄 이상이면 노드 예산(≤9)에 특히 주의한다 — 3행 × 4열 = 12는 이미 초과다.

## 3. Column — 세로 흐름 (플로차트 · 순차 단계)

박스는 가로 중앙 정렬: **x = 464, w = 352** (또는 x = 512, w = 256 좁은 버전).

| 단계 수 | h | 간격 | y 위치 |
|---|---|---|---|
| 3 | 88 | 48 | `228, 364, 500` |
| 4 | 88 | 48 | `160, 296, 432, 568` |
| 5 | 72 | 32 | `164, 268, 372, 476, 580` |

6단계 이상은 세로로 안 들어간다 — 가로 Row로 바꾸거나 단계를 묶는다.

### 척추 + 여백 주석 (spine & marginalia)

세로 흐름은 좌우가 비어 보인다. 그 여백을 **주석 컬럼 2개**로 쓰면 단계마다 훨씬 많은
정보를 담으면서도 노드 수는 그대로다(주석은 노드가 아니다).

| 영역 | 범위 | 정렬 | 담는 것 |
|---|---|---|---|
| 좌측 주석 | x `64 → 440` (376) | `class="sublabel end"` at x=**440** | 무엇이 실행되나(에이전트·조건) |
| 단계 | x `464 → 816` (352) | 중앙 | 단계 이름만 |
| 우측 주석 | x `840 → 1216` (376) | `class="sublabel start"` at x=**840** | 무엇이 나오나(산출물·분기) |

주석 baseline은 **단계 이름과 같은 값**을 쓴다(같은 줄에 정렬). 주석 폭 예산은 376 − 0
= 376px → 등폭 13px 기준 **48자**. 좌우 24px 간격은 고정.

**분기(다이아몬드)**: 마름모는 `w = 224, h = 88`. 중앙 x = 528(폭 224 기준).
분기 후 좌/우 갈래는 x = `160` (좌), `800` (우), w = 320.
**모든 분기는 라벨을 단다** — `Yes` / `No`, `성공` / `실패`. 라벨 없는 분기는
직선처럼 읽혀 "이럴 땐 / 저럴 땐"의 의미를 잃는다.

## 5. 나머지 유형 좌표

### 5.1 Swimlane — 스윔레인 (부서 간 프로세스)

- **라벨 거터**: x `64 → 240` (w 176). 레인 이름은 여기, 우측 정렬(x = 224).
- **레인 영역**: x `256 → 1216` (w 960).

| 레인 수 | 레인 h | 간격 | 레인 y |
|---|---|---|---|
| 3 | 144 | 16 | `176, 336, 496` |
| 4 | 112 | 16 | `160, 288, 416, 544` |

**레인 안 단계 컬럼** (레인 영역 960 기준)

| 단계 수 | w | 간격 | x 위치 |
|---|---|---|---|
| 4 | 216 | 32 | `256, 504, 752, 1000` |
| 5 | 160 | 40 | `256, 456, 656, 856, 1056` |

단계 박스 높이는 레인 h - 48, y는 레인 y + 24.

### 5.2 Timeline / Roadmap — 타임라인

축: `y = 400`, x `64 → 1216`, stroke 1, `--line-strong`.

| 마커 수 | x 위치 |
|---|---|
| 3 | `208, 640, 1072` |
| 4 | `208, 496, 784, 1072` |
| 5 | `208, 424, 640, 856, 1072` |
| 6 | `160, 352, 544, 736, 928, 1120` |

마커는 r = 8 원. **라벨 baseline**: 위 `336`, 아래 `464`.
마커가 5개 이상이면 위/아래를 **번갈아** 배치해 충돌을 피한다.

### 5.3 Quadrant — 2×2 사분면

- 플롯 영역: x `320 → 960` (640), y `160 → 640` (480). 셀 = 320 × 240.
- 셀 중심: `(480, 280) (800, 280) (480, 520) (800, 520)`
- 축선: 세로 x = 640, 가로 y = 400. stroke 1, `--line-strong`.
- 축 라벨: 가로축 baseline `676` (중앙 640), 세로축은 x = `284`에서 `rotate(-90)`.
- 셀 이름은 셀 중심 상단(중심 y - 32), 항목은 그 아래.

### 5.4 Venn — 벤 다이어그램 (2~3 집합만)

- 2원: r = 160, cy = 400, cx = `560, 720` (겹침 160)
- 3원: r = 144, 중심 `(568, 336) (712, 336) (640, 464)`
- 채움 `--paper-2` + `fill-opacity 0.6`, stroke 1 `--line-strong`. 4집합 이상 금지.

### 5.5 Funnel / Pyramid — 퍼널·피라미드 (4단)

| 단 | y | h | w | x |
|---|---|---|---|---|
| 1 | 176 | 104 | 1152 | 64 |
| 2 | 296 | 104 | 928 | 176 |
| 3 | 416 | 104 | 704 | 288 |
| 4 | 536 | 104 | 480 | 400 |

3단이면 2·3·4단(y 296/416/536)을 쓰고 위를 비운다.

### 5.6 Tree / Org — 트리·조직도

- 루트: x = 512, w = 256, y = 176, h = 80
- 2단: y = 344, 3단: y = 512 (h 80 동일)
- 각 단의 x는 **§2 Row X 좌표표**를 그대로 쓴다(폭만 표대로).
- 연결선은 직각 꺾임(`L` 두 번), 사선 금지.

### 5.7 Matrix — 비교 매트릭스

- 헤더 행: y = 176, h = 56. 데이터 행: y = `240, 312, 384, 456, 528` (h 64, 간격 8)
- 컬럼 x는 §2 Row X 좌표표. 첫 컬럼(행 이름)은 좌측 정렬, 나머지는 중앙.
- 셀 구분은 채움이 아니라 **1px `--line` 가로줄**로.

## 6. 노드 내부 스펙

```svg
<rect class="node" x="64" y="328" width="352" height="160" rx="8"
      fill="var(--paper-2)" stroke="var(--line-strong)" stroke-width="1"/>
<text x="240" y="402" class="node-name">주문 서비스</text>
<text x="240" y="426" class="sublabel">order-svc · 3 replicas</text>
```

> 노드 도형에는 반드시 `class="node"`를 준다 — `check.py`의 밀도·오버플로 검사가
> 이 클래스로 노드를 찾는다.

| 항목 | 값 |
|---|---|
| `rx` | **8** — `rx`도 4px 검사 대상이라 `{0, 4, 8}`만 유효(10은 FAIL) |
| 채움 / 테두리 | `--paper-2` / **`--line-strong`**, stroke-width **1** |
| 좌우 패딩 | 20 |
| 노드명 | Pretendard 500, **18px**, `--ink`, `text-anchor: middle` |
| sublabel | JetBrains Mono 400, **13px**, `--muted` |

**baseline 표** (박스 상단 `y` 기준 오프셋)

| 박스 h | 2행: 노드명 / sublabel | 단일행 |
|---|---|---|
| 160 | `y + 74` / `y + 98` | `y + 86` |
| 120 | `y + 54` / `y + 78` | `y + 66` |
| 96 | `y + 42` / `y + 66` | `y + 54` |
| 88 | — | `y + 50` |
| 80 | — | `y + 46` |
| 72 | — | `y + 42` |

> `<text>`의 `x`/`y`는 **4px 규칙 대상이 아니다.** 베이스라인은 광학 중심에 맞춰야
> 하므로 4의 배수로 강제하면 오히려 어긋난다. 4px 규칙은 `rect`/`circle`/`line`/
> `polygon` 등 **도형 좌표와 치수**에만 적용된다.

### 초점(focal) 표시 — 채우지 말고 점을 찍는다

```svg
<rect class="node focal" ... stroke="var(--accent)" stroke-width="2"/>
<circle class="dot" cx="{x+w-24}" cy="{y+24}" r="8" fill="var(--accent)"/>  <!-- 시그니처 점 -->
```

`r = 8`(4의 배수)에 중심을 노드 우상단에서 24씩 안쪽으로. 타임라인 마커 등 점 자체가
노드인 경우도 `r = 8`로 통일한다.

초점은 **1~2개**. 3개째부터는 초점이 아니라 배경이다.

### 커넥터

```svg
<defs>
  <marker id="d1-arrow" viewBox="0 0 8 8" refX="8" refY="4"
          markerWidth="8" markerHeight="8" orient="auto-start-reverse">
    <path d="M0 0 L8 4 L0 8 Z" fill="var(--line-strong)"/>
  </marker>
</defs>
<line x1="416" y1="408" x2="464" y2="408"
      stroke="var(--line-strong)" stroke-width="1.5" marker-end="url(#d1-arrow)"/>
```

- Row 커넥터의 y는 **박스 y + h/2** (h=96 → y+48).
- 꺾일 땐 `<path d="M a b L a c L d c">` 직각. 사선·베지어 금지.
- 교차가 3개 이상 = 유형 선택 오류. 스윔레인/레이어로 바꾼다.
- `stroke-width`는 4px 규칙 **대상 아님** (1, 1.5, 2 사용).

## 7. 라벨 예산 (오버플로 방지)

SVG `<text>`는 넘쳐도 잘리지 않고 **박스 밖으로 삐져나온다.** 미리 글자 수를 지킨다.

폭 추정: **한글·CJK ≈ 1.0 × font-size, 비례 Latin ≈ 0.55 × font-size,
등폭(JetBrains Mono) Latin ≈ 0.6 × font-size** — 글자당.
가용 폭 = 박스 폭 − 40 (좌우 패딩 20).

sublabel은 **등폭**이라 같은 글자 수라도 노드명보다 넓다. 이걸 놓치면 넘친다.

| 박스 폭 | 가용 | 노드명(18px) Latin | 노드명(18px) 한글 | sublabel(13px 등폭) |
|---|---|---|---|---|
| 1152 (전폭 레이어) | 1112 | 112자 | 61자 | **142자** |
| 544 | 504 | 50자 | 28자 | 64자 |
| 352 | 312 | 31자 | 17자 | 40자 |
| 240 | 200 | 20자 | 11자 | 25자 |
| 208 | 168 | 16자 | 9자 | 21자 |
| 152 | 112 | 11자 | 6자 | 14자 |

초과하면 순서대로: ① 더 짧은 명사구로 줄인다 → ② `<tspan>` 2줄(baseline 간격 22)
→ ③ 그래도 안 되면 노드 수를 줄여 박스를 넓힌다. **폰트를 줄여 밀어 넣지 않는다.**

`check.py`가 이 예산으로 오버플로를 검사한다 — `class="node"`인 도형(`rect`/`polygon`/`circle`/`ellipse`) 안에 앵커가 들어간 `<text>`를 측정하며,
`text-anchor`(start/middle/end)를 반영해 좌우 이탈을 모두 본다. **노드 밖에 있는
여백 주석(§3)은 측정 대상이 아니므로** 표의 48자 예산을 직접 지킨다.

## 8. 다른 캔버스 파생 규칙

| | slide-4x3 (1024×768) | social-og (1200×630) |
|---|---|---|
| 마진 | 64 | 56 |
| content x | 64 → 960 (W 896) | 56 → 1144 (W 1088) |
| 본문 영역 y | 160 → 704 (H 544) | 144 → 576 (H 432) |

Row 폭 파생: `w = floor4((W − gap × (N−1)) / N)`, 남는 픽셀은 우측 마진에 흡수시킨다
(좌측 시작 x는 마진 그대로). 결과가 4의 배수인지 **직접 검산**한 뒤 쓴다.
