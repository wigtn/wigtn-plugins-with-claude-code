# 12개 유형 — 무엇을 언제 그리나

유형은 **취향이 아니라 데이터의 모양**이 정한다. 아래 라우팅 표에서 먼저 좁히고,
해당 절에서 "쓰면 안 되는 경우"를 반드시 확인한다. 유형이 틀리면 아무리 예쁘게
그려도 읽히지 않는다.

## 빠른 라우팅

| 말하려는 것 | 유형 |
|---|---|
| 시스템이 무엇으로 이루어져 있나 | **Architecture** |
| 데이터/요청이 어떤 순서로 흐르나 | **Pipeline** |
| 조건에 따라 갈라지는 로직 | **Flowchart** |
| 누가 누구에게 언제 메시지를 보내나 | **Sequence** |
| 여러 부서/역할이 한 프로세스를 나눠 하나 | **Swimlane** |
| 추상화가 쌓여 있나 | **Layers** |
| 언제 무슨 일이 있(었)나 | **Timeline** |
| 두 기준으로 항목들을 자리매김 | **Quadrant** |
| 여러 항목을 여러 기준으로 비교 | **Matrix** |
| 포함/소속 관계 | **Tree** |
| 집합이 겹치나 (2~3개) | **Venn** |
| 단계마다 줄어드나 / 순위가 있나 | **Funnel** |

> **수치 크기 비교**(막대·꺾은선·산점도·히트맵)는 이 스킬이 아니라 `dataviz` 스킬.

---

## 1. Architecture — 시스템 구성

**쓸 때**: 컴포넌트와 그 연결을 보여줄 때. 제안서 AS-IS/TO-BE, 시스템 개요.
**안 쓸 때**: 순서가 핵심이면 Pipeline, 실행 순서가 핵심이면 Sequence.

- 노드 예산: **4~7** (그룹 박스는 노드로 세지 않음)
- 좌표: §2 Row (2~3행) 또는 Row + 그룹 사각형
- 그룹은 채움 없이 `--line` 1px 점선(`stroke-dasharray="4 4"`) + 좌상단 라벨
- 외부 시스템은 sublabel에 `external` 표기, 채움을 `--paper`로 낮춘다

## 2. Pipeline — 단계적 흐름

**쓸 때**: 분기 없는 선형 처리(수집 → 정제 → 적재 → 서빙).
**안 쓸 때**: 분기·되돌아감이 있으면 Flowchart.

- 노드 예산: **3~4** (화살표 간격 때문에 5 이상은 화살표를 뺀다)
- 좌표: §2 Row 1행 (`y = 328`, h = 160) — 1행은 h=160이다. h=96은 3행짜리 값이다
- 각 노드 sublabel에 처리 시간·기술 1개만. 두 줄 이상 쓰지 않는다.

## 3. Flowchart — 조건 분기

**쓸 때**: "이럴 땐 A, 저럴 땐 B"가 핵심일 때.
**안 쓸 때**: 분기가 하나도 없으면 Pipeline. 분기가 4개 이상이면 Matrix나 표.

- 노드 예산: **5~8** (다이아몬드 포함)
- 좌표: §3 Column + 분기 좌/우 (x 160 / 800)
- **모든 분기에 라벨** (`Yes`/`No`). 라벨 없는 분기는 직선처럼 읽힌다.
- 마름모는 `<polygon>`, w 224 × h 88

## 4. Sequence — 시간축 메시지

**쓸 때**: 액터 간 호출 순서·왕복이 핵심일 때(인증 플로우, 결제 승인).
**안 쓸 때**: 액터가 2개 이하면 Pipeline이 더 읽기 쉽다.

- 액터 예산: **3~5**, 메시지 **≤ 8**
- 액터 헤더는 §2 Row X 좌표표 (h = 64, y = 176), 라이프라인은 각 박스 중심 x에서
  y `240 → 640` 세로선 (`stroke-dasharray="4 4"`)
- 메시지 화살표 y: `288`부터 **48씩** 증가. 라벨은 화살표 위 baseline −8

## 5. Swimlane — 부서 간 프로세스

**쓸 때**: "누가" 하는지가 "무엇을" 하는지만큼 중요할 때. RACI, 승인 프로세스.
**안 쓸 때**: 담당이 하나면 Pipeline.

- 레인 **3~4**, 레인당 단계 **≤ 5**, 총 노드 **≤ 9**
- 좌표: §5.1
- 레인 배경은 홀수 레인만 `--paper-2`, 짝수는 `--paper` (얼룩 줄무늬로 구분)

## 6. Layers — 계층 스택

**쓸 때**: 위가 아래에 의존하는 구조(인프라 → 플랫폼 → 앱, 거버넌스 계층).
**안 쓸 때**: 계층이 아니라 그냥 목록이면 텍스트로 쓴다.

- 레이어 **3~5**
- 좌표: §4
- 아래로 갈수록 `--paper-2` 채움을 유지하되 **색을 진하게 만들지 않는다**(위계는
  위치가 이미 표현한다). 레이어 간 화살표는 넣지 않는다.

## 7. Timeline / Roadmap — 시간축

**쓸 때**: 마일스톤, 분기별 로드맵, 프로젝트 페이즈.
**안 쓸 때**: 기간의 **겹침**이 핵심이면 간트형 막대가 필요하다 — Matrix 좌표에
가로 막대를 올려 쓴다.

- 마커 **3~6**
- 좌표: §5.2
- 지난 구간은 `--muted`, 현재/다음은 `--ink`, 강조 마일스톤 1개만 악센트 점

## 8. Quadrant — 2×2

**쓸 때**: 두 축으로 우선순위를 정할 때(임팩트 × 노력, 리스크 × 빈도).
**안 쓸 때**: 축이 3개 이상이면 Matrix. 항목이 10개 넘으면 산점도(`dataviz`).

- 항목 **4~8**
- 좌표: §5.3
- 축 이름은 반드시 방향을 밝힌다: `노력 (낮음 → 높음)`
- 셀 이름(예: `Quick Wins`)은 있으면 좋고, 없으면 비워둔다. 억지로 짓지 않는다.

## 9. Matrix — 비교 매트릭스

**쓸 때**: 항목 × 기준 비교(도구 선정, 권한 매트릭스).
**안 쓸 때**: 기준이 1개면 그냥 정렬된 목록.

- 행 **≤ 5**, 열 **≤ 4**
- 좌표: §5.7
- 셀 값은 `●` / `○` / `—` 또는 짧은 단어. 문장 금지.
- 추천 행/열 **1개**만 악센트 테두리 + 시그니처 점

## 10. Tree / Org — 계층 소속

**쓸 때**: 조직도, 모듈 소유권, 분류 체계.
**안 쓸 때**: 깊이가 4단 이상이면 들여쓴 목록이 더 읽기 쉽다.

- 깊이 **≤ 3**, 노드 **≤ 9**
- 좌표: §5.6
- 연결선은 직각 꺾임. 사선 금지.

## 11. Venn — 집합 겹침

**쓸 때**: 역할·범위의 공통분모가 메시지일 때.
**안 쓸 때**: 집합이 4개 이상. (읽을 수 없다 — Matrix로 바꾼다.)

- 집합 **2~3**
- 좌표: §5.4
- 교집합 영역에 들어가는 텍스트는 **3~4단어**. 넘치면 밖으로 빼고 지시선.

## 12. Funnel / Pyramid — 단계 감소·순위

**쓸 때**: 전환 퍼널, 우선순위 피라미드, 데이터 계층(브론즈/실버/골드).
**안 쓸 때**: 감소량이 실제 수치로 중요하면 막대 차트(`dataviz`).

- 단 **3~4**
- 좌표: §5.5
- 각 단 우측에 수치/비율 1개(모노 13px). 단 자체 폭이 이미 크기를 말하므로
  색으로 또 강조하지 않는다.

---

## 밀도 초과 시 (노드 > 9)

순서대로 시도한다.

1. **묶는다** — 개별 마이크로서비스 5개 → `주문 도메인 (5)` 한 노드 + sublabel
2. **뺀다** — 청중이 임원이면 캐시·큐·리트라이는 메시지에 기여하지 않는다
3. **쪼갠다** — 개요 1장 + 상세 1장. 한 장에 다 넣지 않는다
4. **유형을 바꾼다** — 노드가 많다는 건 대개 Architecture로 그릴 걸
   Layers/Swimlane으로 그려야 한다는 신호다

무엇을 뺐는지는 **Step 2 선언에 반드시 적는다.** 조용한 생략은 거짓말이 된다.
